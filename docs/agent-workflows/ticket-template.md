# Improvement ticket

Use this structure in a GitHub issue. Replace the prompts with concrete evidence; omit fields that genuinely do not apply. Discovery may save the same structure locally when publication was not requested.

## Problem and evidence

Name the behavior or maintenance cost. Link relevant code at the inspected commit and existing tests. Distinguish observed failure, verified missing protection, and an unconfirmed hypothesis.

## Expected benefit

Explain the impact of solving this problem and why it is worth the estimated effort.

## Acceptance criteria

- Observable outcome and how it will be demonstrated.
- Required behavior and compatibility that must remain intact.

## Scope and exclusions

State the intended boundary and related work excluded from this ticket.
